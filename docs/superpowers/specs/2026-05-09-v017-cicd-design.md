- **バージョン**: v0.17
- **タスク**: NDG-5 Phase 5c（親: [NDG-5 OSS リリース準備](https://www.notion.so/350062c9be5c8129bd80d6913e8c0e83)）
- **作成日**: 2026-05-09
- **目的**: GitHub Actions による自動テスト・自動ビルド・依存更新を整備し、OSS としての品質保証と pre-built image 配布を実現する

## 背景

NDG-5（OSS リリース準備）4 Phase のうちの 5c。

- **Phase 5a（v0.15、完了）**: LICENSE / README / CONTRIBUTING / SECURITY / .env.example
- **Phase 5b（v0.16、完了）**: 配布用 docker-compose + Dockerfile + Keycloak realm 自動 import
- **Phase 5c（本タスク、v0.17）**: GitHub Actions test/build + dependabot + PR template
- **Phase 5d（v1.0-rc 直前）**: CHANGELOG / release.yml / v1.0 移行ガイド

## ゴール

1. **PR / push で自動テスト**: typecheck と pnpm test (unit + schema + RLS) が走り、green でないとマージ不可（後日 branch protection で運用）
2. **main / タグ push で自動 image build**: `ghcr.io/tetsukame/nudge` に Docker image を push、ユーザーは `docker pull` で配布版を即取得可能に
3. **自動依存更新**: dependabot で npm / docker base image / github-actions の脆弱性・更新を週次 PR 化
4. **PR テンプレート**: これまでの PR (#9 #10 #11) で繰り返し書いてきた構造をテンプレ化、外部コントリビュータの参入障壁も下げる

## スコープ外

- **Branch protection ルール**: GitHub 側の手動設定。本 PR ではワークフロー自体のみ追加
- **release.yml（タグ push でリリースノート自動生成）**: Phase 5d で対応
- **Codecov 等のカバレッジ計測**: 将来的に検討
- **integration テスト** (`pnpm test:integration`): 本 Phase では PR トリガーから除外（実行時間と Docker リソース消費が大きい）。Phase 5d で main push 時のみ等の運用検討

## `.github/workflows/test.yml`

### トリガー

- `pull_request`（branches: [main]）
- `push`（branches: [main]）

PR で常時走らせ、main への直接 push でも走らせる（hotfix 等を想定）。

### ジョブ

- runs-on: `ubuntu-latest`（Docker daemon が自動起動済み、testcontainers がそのまま動く）
- Node.js 20 + pnpm 9（corepack 経由でセットアップ）

### Steps

1. **checkout**: `actions/checkout@v4`
2. **Setup Node.js**: `actions/setup-node@v4`、Node 20、pnpm キャッシュ有効
3. **corepack enable**: pnpm 利用準備
4. **pnpm install**: `--frozen-lockfile`
5. **typecheck**: `pnpm typecheck`
6. **test**: `pnpm test`（unit + schema + RLS、testcontainers が PG コンテナを起動）

### concurrency

```yaml
concurrency:
  group: test-${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true
```

同一 PR で push 連発した場合、古いランをキャンセルして無駄な実行を防ぐ。

### Permissions

- `contents: read` のみ（テスト実行に書き込み権限は不要）

## `.github/workflows/build.yml`

### トリガー

- `push`（branches: [main]）→ `:latest` と `:main-<sha7>` タグ
- `push`（tags: ['v*']）→ `:<tag>` と `:latest` タグ

### ジョブ

- runs-on: `ubuntu-latest`
- AMD64 のみのビルド（ARM64 は将来的に検討、所要時間とリソースのトレードオフ）

### Steps

1. **checkout**: `actions/checkout@v4`
2. **Set up Docker Buildx**: `docker/setup-buildx-action@v3`
3. **Login to ghcr.io**: `docker/login-action@v3`、`registry: ghcr.io`、`username: ${{ github.actor }}`、`password: ${{ secrets.GITHUB_TOKEN }}`
4. **Extract metadata**: `docker/metadata-action@v5` で tag 名・SHA からイメージタグ自動生成
5. **Build and push**: `docker/build-push-action@v5` で `Dockerfile` をビルド、layer cache 利用、push

### Image tags の生成ルール

| トリガー | タグ |
|---|---|
| `push to main` | `:latest`, `:main-<sha7>` |
| `push tag v0.16` | `:v0.16`, `:0.16`, `:latest` |
| `push tag v0.16-rc1` | `:v0.16-rc1`（latest は更新しない） |

`docker/metadata-action` の標準ルールで実現可能。

### Permissions

- `contents: read`（チェックアウト用）
- `packages: write`（ghcr.io への push）

### 注意点

- 初回 push 後、GitHub の Packages 設定で **「Inherit access from source repository」を有効化** または image を **明示的に public** にする手動操作が必要
- README に「初回セットアップ時の image 公開設定」を注記

## `.github/dependabot.yml`

### 監視対象

| ecosystem | 内容 |
|---|---|
| `npm` | `package.json` の依存（dependencies + devDependencies） |
| `docker` | `Dockerfile` の `FROM` で参照される base image |
| `github-actions` | `.github/workflows/` 内の actions |

### スケジュール

- 週次（毎週月曜）

### グルーピング

- `npm`: minor / patch をまとめて 1 PR、major は個別 PR
- `docker` / `github-actions`: 個別 PR

### PR 数制限

- 各 ecosystem ごとに最大 5 件（過剰な PR 量を防ぐ）

### Pre-built image を使う（最速、ビルド不要）

`docker compose up --build` でローカルビルドする代わりに、ghcr.io から事前ビルド済みイメージを pull できます：

\`\`\`yaml
# docker-compose.override.yml （以下の内容で作成）
services:
  web:
    image: ghcr.io/tetsukame/nudge:latest
    build: !reset
  worker:
    image: ghcr.io/tetsukame/nudge:latest
    build: !reset
  migrate:
    image: ghcr.io/tetsukame/nudge:latest
    build: !reset

docker compose --env-file .env.demo up -d
\`\`\`
